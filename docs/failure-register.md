Source: rebuild specification §6 (incidents #1–#15) and legacy repository
`blitzer04/etf-crowding-monitor` (read-only reference). Classification follows the
spec: an **incident** is supported by a prior audit or patch; a **guardrail** is a
known failure class that is ruled out in advance. A guardrail is not a claim that
the defect occurred in production. The "Regression tests" column names the test
module(s) that must keep failing loudly if the defect class comes back.

## Source-schema evidence recorded during the rebuild

- 2026-10-19: one Yahoo `v8/finance/chart/SPY` request (2024-07-01..2024-07-10,
  `interval=1d`, `includeAdjustedClose=true`) returned HTTP 200 without crumb
  authentication. Observed shape: `chart.{result,error}`; `result[0]` keys
  `meta`, `timestamp`, `indicators`; `meta.symbol = "SPY"`,
  `meta.exchangeTimezoneName = "America/New_York"`, `meta.instrumentType = "ETF"`;
  `timestamp` values are the 09:30 America/New_York session open in epoch seconds;
  `indicators.quote[0]` has `open, high, low, close, volume`;
  `indicators.adjclose[0].adjclose` is a parallel list. Volumes were JSON integers;
  adjusted closes were float32-quantized decimals. `events` is absent when no
  dividend/split falls in range. The 2024-07-04 holiday was absent; 2024-07-03
  (early close) was present. This is one observation, not a documented contract;
  the endpoint is undocumented and unlicensed.
